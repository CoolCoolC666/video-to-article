## 一、需求拆成两个决定

| 决定 | 选择 | 理由 |

| 包形态 | **精简版**（只带云端链路） | 课堂机不需要本地模型；且本地 ASR 栈就算打进去也要另外下模型权重（~1–2GB），并不能离线用 |

## 二、关键技术事实

**重依赖全是延迟导入。** torch / transformers / qwen_asr / funasr / faster_whisper
在 `src/video_to_article/` 里**只在函数体内 import**（`media/qwen_asr.py`、
`media/audio.py`、`text_utils.py`）。GUI 启动与云端转写都不需要它们 ——
但 PyInstaller 会照 import 图把 torch 整棵拖进来（约 2.5 GB）。

→ **精简版只需 excludes 掉这几个包**，不需要改任何业务代码。

**funasr 没装。** 原 spec 里 `datas += collect_data_files("funasr")` 没有 try 保护，
照原样构建会直接崩。fork 早已改用 qwen_asr，funasr 属于历史包袱。

**运行时只读顶层配置。** `active_profile` 只被 GUI 设置页和 MCP 用，
`config.py` 不做档案合并 —— 所以演示配置只要保住顶层值即可。

## 三、怎么构建

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build_gui_onedir.ps1 -Slim -Demo -SkipReleaseDir
```

| 开关 | 作用 |
|---|---|
| `-Slim` | 设 `YLANS_SLIM=1`，spec 据此排除本地 ASR 栈 |
| `-Demo` | 生成演示 config.json + 放入课堂速查 |
| `-SkipReleaseDir` | 不留 ~1GB 的版本化目录，只出 zip |

新增文件：

- `packaging/make_demo_config.py` —— 生成演示配置（只留必需密钥 + 清本机绝对路径），
  并把课堂速查写成中文名（**必须由 Python 落盘**：PS 5.1 会解码坏 .ps1 里的中文字面量）
- `packaging/demo_README.txt` —— 课堂速查正文

## 七、课堂实测暴露的 bug：下载成功却报「音频文件未找到」

**现象**（用户首次在打包版上跑 B 站链接）：

    [download] 100% of 10.58MiB in 00:00:00 at 12.57MiB/s
    [ERROR] 下载失败: 音频文件未找到（下载可能已完成但扩展名不匹配）: ...\Bilibili-张张游泳池\audio

**但文件就在那儿**：`data/bilibili/Bilibili-张张游泳池/audio/考前..._BV11fsh68EyT.mp3`（4.79MB）。
报错信息里给的路径与文件所在路径**完全一致**，源码的查找函数事后又能找到它。

**排查过程**（都排除了）：

| 假设 | 结论 |
|---|---|
| 路径太长 / 含中文 | 排除 —— 把源码复制到**同样的长中文路径**下跑，正常 |
| ffmpeg 没接上 | 排除 —— 内置 ffmpeg 在 `ffmpeg\` 下，`ffmpeg_location_for_ytdlp()` 能找到 |
| 扩展名不匹配 | 排除 —— 磁盘上就是 `.mp3`，在 AUDIO_EXTS 里 |
| 两次取到的标题不同 | 未复现 —— 字幕阶段（Bilibili API）与下载后（yt-dlp）的标题实测一致 |
| 目录算错 | 排除 —— 报错路径与实际路径一致 |

**根因（代码级）**：文件是用**下载那一刻**算出的 stem（`out_stem`）写进磁盘的，
查找却用**下载之后**用 `info` 重算的 stem（`_media_lookup_stems`）。
这两步之间标题一旦不一致（字幕阶段走 Bilibili API、下载后走 yt-dlp），
文件就在磁盘上却按新标题找不到 —— 报的还是「文件未找到」这种看不出真相的错。

**修法**（`media/download.py`）：

1. **根因**：把 `out_stem` 也纳入查找候选 —— 文件就是用它写的，当然要用它找。
2. **兜底**：`_find_by_video_id()` 按视频 ID 找（文件名里始终带 ID，标题变不影响）。
3. **诊断**：报错信息现在会列出**目录里到底有什么**、**尝试过哪些文件名**。
   以后再遇到同类问题，10 秒就能定位。

**顺带加的能力**：`YilanChengWen.exe --cli <参数>` —— 窗口版程序也能跑命令行，
输出落 `logs/cli_run.log`。既是课堂机没有图形界面时的入口，
也是**在打包环境里验证整条链路**的唯一办法（GUI 没法脚本化驱动）。

**验证**：修复后在**打包版的真实条件**下（无 cookies → 字幕失败 → 走下载路径）
跑通完整链路：下载 6.5s → R2 公网 URL → DashScope 提交/轮询 4 次 → 4496 字符
→ MiniMax 出稿 200 → raw.md + general_article.md + 封面落盘，全程 1 分 43 秒。

## 八、真正的「上传路径」根因：boto3 没进包

打包版跑起来的第一个报错不是「音频文件未找到」，而是：

    [ERROR] 转写失败: 缺少依赖 boto3，请先运行: pip install -r requirements.txt

**boto3 是 R2 / OSS 上传用的 S3 客户端**（`cover.py` 的 `upload_to_s3_compatible`），
而它是这么加载的：

    boto3 = import_required("boto3", "boto3")     # → __import__("boto3")

**PyInstaller 的静态分析看不见 `__import__(name)`** —— 变量形式的导入它认不出来，
所以 boto3 根本没被打进包。表现出来就是：音频下载得好好的，
一到「上传音频换公网 URL」这步就报「缺少依赖 boto3」，整条链断在那儿。

**修法**（三层，防止再犯）：

1. `packaging/video_to_article_gui.spec`：hiddenimports 显式加 `"boto3"`。
2. `scripts/build_gui_onedir.ps1`：构建后断言 `_internal\boto3` 存在，
   缺了就直接 fail（别等客户机上炸）。
3. `tests/smoke_packaging_hiddenimports.py`：**自动**扫出源码里所有
   `import_required("X")` 的模块，逐个核对是否在 spec 的 hiddenimports 里
   （精简版刻意排除的本地引擎栈除外）。以后新增懒加载依赖，忘了写 spec 就红。
